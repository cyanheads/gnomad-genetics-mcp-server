# 0.5.2 — 2026-11-01

## Added

- **`gnomad_get_variant` `variant_not_found_other_build`**: an absent coordinate ID whose string also resolves on the other reference build fails with this reason, and `candidates` lists the IDs it lifts to. The lift runs once after the batch settles, in requests of at most 25 IDs each; a reply naming IDs other than the ones asked for is discarded, and an error, a spent deadline, or an empty result leaves plain `variant_not_found`. rsIDs are never lifted. The variant resource raises the same reason with `candidates` in `error.data`, and `gnomad_variant_triage` settles the build before the coverage step ([#58](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/58)).
- **`gnomad_list_gene_variants` `offset`, `limit`, `next_offset`**: pages the filtered rows; `total` counts every row the filters keep and `qc_filtered` every match, on every page. gnomAD returns a target whole, so each page re-fetches it: filter and raise `limit` for a large target. A page past offset 0 never stages ([#59](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/59)).
- **`gnomad_list_gene_variants` and `gnomad_search_clinvar` echo**: the list tool returns `target`, `target_kind`, and `filters`; the ClinVar tool returns `gene` and `filters`, with `clinical_significance` as applied. Unset filters are `null` ([#70](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/70)).
- **`GNOMAD_NORMALIZE_IDS`** (default `true`): rewrites identifier spellings with one clear reading before validation, on the tools, the variant and gene-constraint resources, and `gnomad_variant_triage`. These are an uppercase rsID, `1:55039974:G:T` and `chr1:55039974:G:T` variant IDs, `chr1:55,039,447-55,064,852` regions, and lowercase or versioned `ENSG`/`ENST` IDs. Each rewrite is logged and counted; `false` restores the strict rejections ([#62](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/62)).
- **`GNOMAD_CLAMP_LIMITS`** (default `true`): a `limit` above its cap clamps to the cap with a notice, a log line, and a counter, and the schema advertises no `maximum`. `false` rejects it and advertises the cap ([#63](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/63)).

## Changed

- **`limit` defaults and caps**: `gnomad_list_gene_variants` 25 (cap 3,000), `gnomad_search_clinvar` 10 (cap 1,500), `gnomad_dataframe_query` 25 (cap 3,000); a call with no `limit` pages on through `next_offset` ([#63](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/63)).
- **`gnomad_dataframe_query` pages**: a page holds `limit` rows or the result's remainder, and ends before a row that would take its row JSON past 4,000,000 characters (the 10,000-character page budget is gone). `row_too_large` fires only when the first row alone passes that ceiling. `BIGINT` columns arrive as strings; `CAST(col AS INTEGER)` returns a number ([#60](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/60)).
- **`gnomad_search_clinvar` `clinical_significance`**: `pathogenic`, `likely pathogenic`, `uncertain significance`, `vus`, `likely benign`, `benign`, and `conflicting` search ClinVar's classification properties, so `total_found` counts the matches rather than the all-fields candidates. The term is case-insensitive, and `vus` now returns `Uncertain significance` rows. Other terms behave as before ([#67](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/67)).
- **Canvas off (`CANVAS_PROVIDER_TYPE=none`)**: `gnomad_list_gene_variants` and `gnomad_search_clinvar` return every row of a page inline, so `limit` is the only page boundary and `next_offset` no longer skips rows. `gnomad_dataframe_query`, `gnomad_dataframe_describe`, and `gnomad_dataframe_drop` leave `tools/list`, and the server instructions and row-tool descriptions stop naming them ([#59](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/59), [#72](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/72)).
- **`gnomad_get_variant` `variant_not_found` recovery**: no longer endorses absence before the build is ruled out. The tool description notes that a string valid on one build can name a different variant on the other ([#58](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/58)).
- **`gnomad_list_gene_variants` region example**: `1-55039447-55064852` ([#70](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/70)).

## Fixed

- **Unknown gene or transcript**: `gnomad_list_gene_variants` and `gnomad_get_coverage` fail `gene_not_found` or `transcript_not_found`, naming the reference build, for an unknown or misspelled gene or Ensembl ID and for an unknown or RefSeq transcript ID (`NM_174936.4`), where they returned an empty success. A real gene or transcript with no rows still returns `total: 0` or empty `summaries` ([#56](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/56)).
- **`pass_only` on `gnomad_r2_1`**: a row that fails QC in one callset and passes in the other reads `ac`, `an`, `homozygote_count`, and `af` from the passing callset, and `max_af` filters on that `af`. Without `pass_only` the sum stays ([#78](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/78)).

## Security

- **`gnomad_dataframe_query`**: a page reads at most `limit` rows and ends before a row that would take its row JSON past 4,000,000 characters.
