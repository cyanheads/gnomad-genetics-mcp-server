# 0.3.0 — 2026-09-23

## Added

- **`gnomad_search_clinvar` result windows** ([#28](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/28)) — `offset` and `limit` (1–500, default 500) page the ClinVar match list, and the output adds `total_found`, `truncated`, `next_offset`, and `unavailable_ids` (VariationIDs ESummary returned no summary for). `limit` counts records before the significance and star filters, so a window can return fewer rows.
- **gnomAD-compatible identifiers on ClinVar rows** ([#29](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/29)) — `canonical_spdi`, `rsids`, and `grch38_variant_id` (`chrom-pos-ref-alt`), in the output and on the `clinvar_variants` table. `grch38_variant_id` is set for SNVs, MNVs, and delins, and null for deletions, insertions, duplications, mitochondrial variants, and multi-allele records.
- **Staged-table pointer** ([#21](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/21)) — when either row tool stages a table, its notice names the table and canvas, then `gnomad_dataframe_describe` and `gnomad_dataframe_query`; the server instructions and the `format()` staged line name both tools too.

## Changed

- **ClinVar filters narrow the ESearch term** — `clinical_significance` and `min_review_stars` go into the query so a window holds relevant candidates; the post-fetch filters stay authoritative.

## Fixed

- **Canvas staging decides fit before acquiring a canvas** ([#35](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/35)) — a result that fits inline with no `canvas_id` mints no canvas (`canvas_id: ''`); a supplied `canvas_id` always writes the result to the table, replacing the previous one, and a zero-row result drops it. Staged tables declare column types from the row type, so `af` no longer stages as `BIGINT` and truncates to 0.
- **Responses stay near 24 KB** ([#37](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/37)) — the inline preview is 14,000 JSON characters for `gnomad_list_gene_variants` and 11,000 for `gnomad_search_clinvar` (was 60,000), and the same budget replaces the 100-row cap when the canvas is disabled.
- **`format()` no longer reports a disabled canvas** when a call used none ([#33](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/33)) — the staged line reads "no canvas table for this call".
- **The ClinVar gene is sent as a quoted phrase, `"<gene>"[gene]`** ([#40](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/40)) — query syntax in `gene` no longer detaches the field tag and returns other genes' records; a gene empty after removing `"` matches nothing without a request.
- **Blank inputs read as omitted** ([#31](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/31)) — a blank `gene` or `transcript_id` on `gnomad_list_gene_variants` and `gnomad_get_coverage`, and a whitespace-only `clinical_significance` on `gnomad_search_clinvar`, which previously searched all fields.
- **`gnomad_variant_triage` `dataset` accepts only `gnomad_r4`, `gnomad_r3`, `gnomad_r2_1`, or `exac`** ([#31](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/31)) — any other value is rejected before the chain is generated; blank uses the server default.
- **`gnomad_search_clinvar` declares `upstream_unavailable`** ([#28](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/28)), the reason the service emits for an NCBI failure, in place of the never-emitted `ncbi_unreachable`.
