# 0.2.1 — 2026-08-30

## Added

- **Ambiguous rsID recovery** — `gnomad_get_variant` now returns candidate `variant_id` values for rsIDs that fan out to multiple loci, so callers can retry with an exact coordinate form instead of re-querying blind.
- **gnoMAD attribution in tool-facing text** — the server instructions, tool outputs, and resource documents now surface the Genome Aggregation Database as the primary data source.

## Changed

- **ClinVar request pacing** — the NCBI E-utilities client now enforces process-shared request spacing at the documented rate limit, while still honoring `NCBI_API_KEY` for the higher ceiling.
- **Boundary recovery metadata** — dataset/reference-genome coherence errors now preserve their declared recovery hints across shared schema validation, tool handlers, resources, and the triage prompt.
- **`@biomejs/biome` `^2.5.9` → `^2.5.11`**.
- **`@types/node` `^26.2.0` → `^26.4.0`**.
- **`fast-check` removed** — the repo no longer carries an unused fuzz dependency.

## Fixed

- **Whitespace gene input in `gnomad_search_clinvar`** — direct ClinVar lookups now trim HGNC symbols at the service boundary instead of returning unrelated records for padded inputs.
- **Coordinate-ID validation and normalization** — coordinate-form variant IDs are trimmed, validated, and canonicalized before gnomAD lookups, and invalid forms now fail with the declared `invalid_variant_id` contract instead of surfacing upstream not-found noise.
- **Upstream build integrity** — variant responses now validate the upstream `reference_genome` before labeling output, preventing GRCh37/GRCh38 mismatches from leaking through a coherent request.
- **Constraint metric domains** — pLI, observed/expected values, LOEUF bounds, and Z-scores are validated at the upstream boundary before they enter tool/resource output.
- **Malformed 2xx upstream payloads** — gnomAD and ClinVar parse/schema failures now surface as classified upstream errors instead of raw parse exceptions.
- **Optional ClinVar join degradation** — when the optional `clinvar_variant` field errors, variant hits still return with a `clinvar_unavailable` flag instead of dropping the whole row.
