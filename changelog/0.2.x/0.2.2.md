# 0.2.2 — 2026-09-20

## Changed

- **The stateless session posture is declared in `src/`** via `createApp({ sessionMode })` ([#23](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/23)) — the container and a source, `bunx`, or `npm start` run resolved to different HTTP modes, since the framework schema default `auto` resolves to `stateful`. A deployment's `MCP_SESSION_MODE` still wins where it carries a meaningful value, and `.env.example` now sets `stateless` actively.
- **An invalid tool argument is rejected as `InvalidParams` (`-32602`)** rather than `ValidationError`, carrying `data.reason: "invalid_arguments"` and a `data.recovery.hint` derived from the schema. An unknown root key names the keys the tool does accept.
- **A camelCase spelling of a declared snake_case parameter is rewritten** instead of rejected — `referenceGenome` reaches `reference_genome` — whenever the declared key itself is absent.
- **Tool error `content[]` closes with `(reason … · not retryable)`** whenever the error data carries a `reason` or a boolean `retryable`. `structuredContent` is byte-identical, so a test pinning the text exactly should assert containment instead.
- **`canvas_id` inputs advertise the minted `^[A-Za-z0-9_-]{10}$` pattern** — an id that cannot have been minted is rejected at argument validation (`invalid_arguments`) before any registry lookup, where it previously came back as a missing or expired canvas.
- **Transport and upstream classification** — a caller that disconnects mid-call is `RequestCancelled` (`-32011`); an upstream 500 is `ServiceUnavailable` and retries, and a 501 shares that code but carries `retryable: false` so it does not; a 3xx is `InvalidRequest`.
- **The development skill tree moved from `skills/` to `framework-skills/`** — Claude Code and Codex auto-load a plugin's root `skills/`, so installing this server as a plugin handed them to the agent.
- **Repo surface** — `devcheck` and the packaging scripts are synced to the framework's current set (README version-badge parity, the `lint.truncationAllowlist` config key, Bun 1.4 `bun audit` parsing), `.github/workflows/codeql.yml` is added as the one workflow this repo carries, the README is restructured around a per-capability reference, and the issue templates and plugin manifests are refreshed.

## Fixed

- **The `linux/amd64` image carries the target platform `@duckdb` binding** ([#24](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/24)) — the Dockerfile copied the build stage's `@duckdb` tree over the production install, leaving `gnomad_dataframe_query` and `gnomad_dataframe_describe` unreachable on that leg under `CANVAS_PROVIDER_TYPE=duckdb`.

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.12.3` → `^0.13.6`, carrying upstream security fixes this server inherits: an SSRF DNS-guard bypass on Bun 1.4 Linux, five polynomial-time regexes replaced with linear scans (two of them on client-supplied input), and the upstream request URL dropped from client-facing `error.data`.
- `zod` `^4.4.3` → `^4.6.5`, `@duckdb/node-api` `^1.5.5-r.4` → `^1.5.5-r.5`
- Bun engines floor `>=1.3.0` → `>=1.4.0` (required by the framework)
- dev: `vitest` and `@vitest/coverage-istanbul` `^4.1.11` → `^5.0.1`, `@biomejs/biome` `^2.5.11` → `^2.5.14`, `@types/node` `^26.4.0` → `^26.6.1`, `ignore` `^7.0.6` → `^7.0.9`, `tsc-alias` `^1.9.2` → `^1.9.5`
