# 0.4.1 — 2026-10-14

## Added

- **`bucket_count` and `bucket_size` on each `gnomad_get_coverage` summary** ([#45](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/45)) — the number of gnomAD coverage buckets summarized and their width in bp (1 for a region under 850 bp, wider for larger targets). Depth and fraction values describe buckets, not single bases; `content[]` shows the bucket line.

## Changed

- **`gnomad_get_coverage` `positions` counts target bases** ([#45](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/45)) — the bases inside the summarized buckets (`start..stop` for a region, the exons ±75 bp for a gene or transcript), where it counted buckets before. Bases past a track's outermost records are left out rather than counted as zero ([#48](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/48)).
- **The ClinVar lookup has a 45 s budget per call** ([#44](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/44)) — across every attempt and backoff, shared by every ID in a `gnomad_get_variant` batch; past it the item returns `clinvar_unavailable: true`. The gnomAD requests carry no call-level deadline yet ([#47](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/47)).
- **Docker image** — the `deps` stage deletes musl-only packages (DuckDB's musl bindings) the Debian runtime never loads, via `scripts/prune-musl-packages.ts`. Base images move to `oven/bun:1.4.3`.
- **Repo and packaging** — framework skills and scripts synced to mcp-ts-core 0.13.15; the `server.json` npm entries launch through `npx` without `run start:*` arguments and the HTTP entry fixes `MCP_TRANSPORT_TYPE` as `http`; the package description is shortened across the manifests, README, and Docker label; `.env*` is ignored except templates; the CodeQL workflow runs one job per language; `.mcpbignore` excludes `tests/` and `coverage/`; `.env.example` documents the new framework variables.

## Fixed

- **A failed ClinVar join keeps the variant** ([#44](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/44)) — `gnomad_get_variant` and `gnomad://variant/{dataset}/{variantId}` return the record with `clinvar: null` and `clinvar_unavailable: true`, instead of failing the item as `graphql_error`. gnomAD's errors carry no `path`, so when a reply holds errors beside a populated `variant`, the lookup is re-sent as a variant-only and a ClinVar-only request, each judged alone; a clean or absent reply still costs one request.
- **`gnomad_get_coverage` summaries no longer treat buckets as bases** ([#45](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/45)) — gene and transcript summaries average only the buckets overlapping the exons ±75 bp, not the zero-filled introns between them (PCSK9 genome mean depth 10.2 → 32.5), and a region keeps the bucket covering its first bases.
- **`gnomad_dataframe_drop` fails an unknown or expired canvas as `canvas_not_found`** — with a hint that nothing is left to drop, replacing the framework's re-stage hint.
