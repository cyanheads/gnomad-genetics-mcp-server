# 0.4.0 — 2026-09-30

Breaking for `gnomad_dataframe_query` callers: read `total` instead of `row_count`, and page with `offset`/`limit`, following `next_offset` until it is null — a default call now returns at most 100 rows.

## Added

- **`constraint_release` on `gnomad_get_gene_constraint` and `gnomad://gene/{dataset}/{gene}/constraint`** ([#26](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/26)) — `gnomAD v4.1.2` for `gnomad_r4` and `gnomad_r3` (gnomAD publishes no v3 constraint), `gnomAD v2.1.1` for `gnomad_r2_1`, `ExAC r0.3` for `exac`.
- **`reason` and `recovery` on each `gnomad_get_variant` `failed[]` item** ([#43](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/43)) — the typed reason and the hint the tool declares for it, also rendered in `content[]`. A cancelled call, or a failure with no declared reason, now fails the whole call.
- **`annotation` on each `in_silico` entry** ([#36](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/36)) — the text gnomAD attaches to a score (the SpliceAI event on `gnomad_r3`), or the raw value when it holds no number; `null` for a plain score.

## Changed

- **`gnomad_dataframe_query` returns one page** ([#30](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/30)) — `offset` (default 0) and `limit` (1–500, default 100) select it, and it ends before its rows pass 10,000 characters of JSON. The output adds `offset`, `returned`, `total` (null above the canvas row cap), and `next_offset`; a first row over the budget fails with `row_too_large`.
- **Constraint text states gnomAD's LoF-intolerance guidance per release** ([#26](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/26)) — LOEUF < 0.45 on v4.1.2, < 0.35 on v2.1.1, pLI alone on ExAC — in the tool, the resource, and the `gnomad_variant_triage` prompt, replacing the "v4 beta" and "< 0.6 in v4" wording.
- **Docker image** — a `deps` stage on the build platform installs production dependencies with `--os`/`--cpu`, so each architecture carries its own DuckDB bindings, and `scripts/install-otel.ts` installs the OTel packages at the framework's peer ranges. Base images move to `oven/bun:1.4.2`.
- **Repo and packaging** — framework skills and scripts synced to mcp-ts-core 0.13.10; `.env.example` documents `LOG_TOOL_FAILURE_PAYLOADS` and the per-signal OTLP endpoints; the npm package excludes `dist/*.mcpb`, and the `.mcpb` bundle excludes `docs/idea.md` and `logs/`; `CONTRIBUTING.md`, `SECURITY.md`, and the feature-request form follow the framework template.

## Removed

- **`gnomad_dataframe_query` `row_count`** ([#30](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/30)) — replaced by `total`.

## Fixed

- **Absent coordinate variant IDs read as absent** ([#25](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/25)) — the variant resource fails with `variant_not_found` and a batch item gets the standard not-found failure, instead of `graphql_error`.
- **`exac` serves ExAC constraint** ([#26](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/26)) — it returned gnomAD v2.1.1 metrics; it now reads `exac_constraint`, whose ratios, LOEUF, and flags stay null or empty because ExAC publishes none.
- **Regions gnomAD would reject fail before any fetch** ([#27](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/27)) — an unserved chromosome, a start below 1, or a stop of 1,000,000,000 or more fails as `invalid_region`, and a span of 2,500,000 bp or more as `region_too_large`, instead of retrying as `upstream_unavailable`. A `chr` prefix and lowercase `x`/`y` are accepted.
- **gnomAD's HTTP 500 region messages fail once** ([#39](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/39)) — a region over gnomAD's ~30,000-variant ceiling fails as `region_too_large` with gnomAD's message instead of retrying; `Request timed out`, `Service overloaded`, and rate-limit errors on an HTTP 200 now retry as `upstream_unavailable`.
- **`gnomad_r3` SpliceAI values no longer become `NaN`** ([#36](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/36)) — `"0.00 (no_consequence)"` failed output validation for the whole batch; `value` now holds the score and `annotation` the event.
- **Every service failure carries a declared reason and hint** ([#38](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/38)) — each tool and resource declares every reason its services raise, and the framework fills that surface's declared hint. A failed body read fails as `upstream_timeout` or `upstream_unavailable`.
- **Mitochondrial targets fail as `mitochondrial_unsupported`** ([#42](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/42)) — `M`, `MT`, and `chrM` variant IDs and regions without a fetch, and genes or transcripts gnomAD places on chromosome M, instead of reporting false absence.
- **`bun run test:coverage` exits 0** ([#32](https://github.com/cyanheads/gnomad-genetics-mcp-server/issues/32)) — new tests over the error and edge paths clear the framework's unchanged branch threshold.
